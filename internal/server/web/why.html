A SMALLER TOOL FOR A SPECIFIC JOB

SSH access, without
the long-lived key sprawl.

Ephemeral SSH focuses on one workflow: issue a short-lived OpenSSH user certificate, then let the user connect directly to the destination host.

Why this product exists

Some teams need just-in-time SSH credentials but do not need to adopt a broad privileged access management (PAM) platform solely for certificate issuance. Ephemeral SSH is designed as a small, self-operated issuer that works with OpenSSH’s built-in certificate trust.

01

Short-lived by design

Certificates are capped by the issuer at 15 minutes. OpenSSH checks validity when a connection is authenticated, reducing dependence on long-lived client credentials.

02

Less key distribution

Configure each target to trust the CA once. For this access flow, operators do not need to append every user's public key to every account’s authorized_keys.

03

Direct OpenSSH connection

After issuance, the client connects directly to the target using the normal SSH path. The issuer is not an inline session proxy.

04

Focused operational scope

Run a purpose-built service for SSH certificate issuance when that is the immediate need, and integrate it with the identity and infrastructure controls you already operate.

A FOCUSED TOOL IS A TRADE-OFF

Not a replacement for every PAM program.

Enterprise PAM products may provide approvals, session recording, credential vaulting and rotation, centralized policy, and governance. Ephemeral SSH does not currently implement those capabilities, nor API authentication or requester authorization. Short-lived certificates do not replace them.

Choose a broader PAM solution when those controls are required. Consider Ephemeral SSH only when a team specifically needs SSH certificate issuance and is prepared to provide the surrounding security controls and operations.
